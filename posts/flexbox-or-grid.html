Flexbox 与 Grid，什么时候用哪个

2026.11.12 前端 CSS 6 min read

这两个属性我一开始是混着用的，直到把「一维」和「二维」这个区别想清楚，选择才不再犹豫。

一句话版本

  • Flexbox：沿一条轴排布，处理「一行里怎么分空间」。
  • Grid：同时控制行和列，处理「一块区域怎么切格子」。

Flex 更顺手的场景

导航栏、按钮组、图标加文字、卡片底部的操作区。这些地方的共同点是：元素数量不定，但都在同一行（或同一列）里，只需要分配剩余空间和对齐。 

.toolbar {
  display: flex;
  align-items: center;
  gap: 12px;
}
.toolbar .spacer {
  margin-left: auto;
}

最后一段 margin-left: auto 是很实用的技巧：把某个元素推到行尾，不用额外包裹容器。

Grid 更顺手的场景

整页布局、卡片墙、表单两列对齐。只要你有「列」的概念，并且希望不同行之间的列宽度一致，就该用 Grid。 

.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(240px, 1fr));
  gap: 20px;
}

这一行几乎是我现在写响应式卡片列表的默认方案：列数随容器宽度自动增减，不需要任何媒体查询。

混用很正常

外层用 Grid 划分页面区域，每个区域内部用 Flex 排列内容，是最常见的组合。不必强求「只用一种」。

判断标准不是哪个更新，而是：我在对齐一条线上的东西，还是在切一块区域。
